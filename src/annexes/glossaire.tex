\begin{description}
    \item[Angular] Framework JavaScript développé par Google pour créer des applications web single-page (SPA). Utilisé pour le frontend de BrackX.

    \item[API REST] Application Programming Interface suivant le style REST~: interface permettant au frontend de communiquer avec le backend via des requêtes HTTP.

    \item[Bracket] Représentation en arbre des confrontations d'une phase à élimination directe, montrant la progression des participants jusqu'à la finale.

    \item[better-auth] Librairie d'authentification pour Node.js gérant les comptes, le hachage des mots de passe et les sessions (cookie httpOnly). Utilisée par BrackX pour l'ensemble de l'authentification.

    \item[CI/CD] Continuous Integration / Continuous Deployment~: pratiques d'automatisation des tests et des déploiements pour fiabiliser et accélérer les livraisons.

    \item[CORS] Cross-Origin Resource Sharing~: mécanisme de sécurité du navigateur, configuré côté API pour n'autoriser que l'origine du frontend.

    \item[Docker / Docker Compose] Technologie de conteneurisation. Docker Compose orchestre l'ensemble des services du projet (backend, frontend, base de données, stockage, supervision) via un seul fichier.

    \item[DTO] Data Transfer Object~: objet décrivant et validant la structure des données entrantes d'une requête, associé à class-validator côté NestJS.

    \item[Élimination directe] Format de tournoi où un participant est éliminé dès sa première défaite.

    \item[ESLint] Outil d'analyse statique du code TypeScript détectant erreurs et écarts aux conventions du projet.

    \item[GitLab CI/CD] Service d'intégration continue intégré à GitLab, configuré via un fichier YAML (\texttt{.gitlab-ci.yml}) versionné dans le dépôt.

    \item[Grafana] Outil de supervision utilisé pour visualiser les métriques applicatives et techniques.

    \item[Guard] Composant NestJS contrôlant l'accès à un endpoint~: \texttt{GardeAuthentification} valide la session better-auth avant d'autoriser l'action.

    \item[Head-to-head] Critère de départage des égalités fondé sur le résultat des confrontations directes entre les participants à égalité.

    \item[Jest] Framework de test standard de l'écosystème Node.js, utilisé pour les tests unitaires du backend NestJS.

    \item[Jasmine / Karma] Outils de test natifs d'Angular, utilisés pour les tests unitaires du frontend.

    \item[Merge Request (MR)] Demande de fusion d'une branche vers une autre sur GitLab, soumise à la validation du pipeline CI avant intégration (équivalent GitLab de la pull request).

    \item[Migration] Script versionné décrivant une évolution de la structure de la base de données, appliqué via Prisma.

    \item[NestJS] Framework Node.js pour construire des applications backend modulaires et évolutives. Utilisé pour l'API de BrackX.

    \item[Node.js] Environnement d'exécution JavaScript côté serveur.

    \item[Onboarding] Parcours d'accueil guidant un nouvel utilisateur lors de sa première connexion. Son achèvement est mémorisé en base (champ \texttt{onboardingTermine}).

    \item[ORM] Object-Relational Mapping~: technique faisant correspondre les tables d'une base relationnelle à des objets typés du code.

    \item[OWASP Top 10] Liste de référence des dix risques de sécurité les plus critiques des applications web.

    \item[Pipeline] Ensemble d'étapes automatisées (lint, build, tests) exécutées à chaque modification du code.

    \item[Poules] Format de tournoi où les participants d'un groupe s'affrontent tous, un classement déterminant les qualifiés.

    \item[Prisma] ORM moderne pour Node.js et TypeScript, suivant une approche schéma-first avec migrations versionnées et client typé.

    \item[Qualification inter-phases] Règle définissant combien de participants passent d'une phase à la suivante et selon quel parcours (y compris saut d'étape).

    \item[Recette] Phase de tests fonctionnels validant l'application au regard des résultats attendus avant livraison.

    \item[RGAA] Référentiel Général d'Amélioration de l'Accessibilité (version 4.1)~: référentiel officiel français pour l'accessibilité numérique.

    \item[Ronde suisse] Format de tournoi où, à chaque ronde, les participants de score voisin sont appariés sans jamais se réaffronter. Le classement s'établit aux points, sans élimination directe.

    \item[Rollback] Retour à une version précédente de l'application en cas de problème après déploiement.

    \item[Saut d'étape] Mécanisme de qualification permettant à certains rangs d'une phase de se qualifier directement pour une phase ultérieure en sautant une phase intermédiaire.

    \item[Session] Identifiant d'authentification émis par better-auth après connexion, conservé en base et transporté par un cookie \texttt{httpOnly} (inaccessible au JavaScript) à durée de vie limitée avec prolongement glissant.

    \item[Smoke test] Test de fumée~: vérification rapide des fonctionnalités critiques après chaque déploiement.

    \item[Tiebreak] Cascade de critères appliquée pour départager des participants à égalité (head-to-head, différentiel, barrage).

    \item[TMA] Tierce Maintenance Applicative~: maintenance et évolution de l'application après livraison.

    \item[TypeScript] Extension typée de JavaScript apportant robustesse et maintenabilité au code.

    \item[User Story] Description courte d'une fonctionnalité du point de vue de l'utilisateur, au format « En tant que… je peux… afin de… ».

    \item[Versionnement sémantique] Convention de numérotation des versions \texttt{major.minor.patch} (par ex. v1.0.0).

    \item[WebSocket] Protocole de communication bidirectionnelle temps réel, envisagé via les gateways NestJS pour les futures notifications.
\end{description}

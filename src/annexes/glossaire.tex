\begin{description}
    \item[Angular] Framework JavaScript développé par Google pour créer des applications web single-page (SPA). Utilisé pour le frontend de BrackX.

    \item[API REST] Application Programming Interface suivant le style REST~: interface permettant au frontend de communiquer avec le backend via des requêtes HTTP.

    \item[better-auth] Librairie d'authentification pour Node.js gérant les comptes, le hachage des mots de passe et les sessions. Fait partie des dépendances suivies par le processus de mise à jour.

    \item[CHANGELOG / Keep a Changelog] Fichier documentant les évolutions de chaque version, tenu selon le format standard \emph{Keep a Changelog} (rubriques Ajouté, Modifié, Corrigé, Sécurité).

    \item[Checkmarx] Suite d'analyse de sécurité applicative (SAST et SCA) utilisée en entreprise (Enedis). Reproduite ici par des équivalents open-source (Semgrep, Trivy).

    \item[CI/CD] Continuous Integration / Continuous Deployment~: pratiques d'automatisation des tests et des déploiements pour fiabiliser et accélérer les livraisons.

    \item[Conventional Commits] Convention de nommage des messages de commit (\texttt{fix:}, \texttt{feat:}, \texttt{chore:}\ldots) permettant d'automatiser la génération du journal des versions.

    \item[Core Web Vitals] Indicateurs de performance perçue mesurés côté utilisateur~: LCP (temps de chargement du contenu principal), INP (réactivité aux interactions) et CLS (stabilité visuelle).

    \item[Dependency Dashboard] Tableau de bord (issue GitLab) généré par Renovate, recensant en permanence l'état des dépendances et les mises à jour en attente.

    \item[Docker / Docker Compose] Technologie de conteneurisation. Docker Compose orchestre l'ensemble des services du projet (backend, frontend, base de données, supervision) via un seul fichier.

    \item[Élimination directe] Format de tournoi où un participant est éliminé dès sa première défaite.

    \item[Exempt (\emph{bye})] En ronde suisse à effectif impair, statut de l'équipe non appariée lors d'une ronde, qui se voit crédités les points correspondants sans jouer de match.

    \item[GitLab CI/CD] Service d'intégration et de déploiement continus intégré à GitLab, configuré via un fichier YAML (\texttt{.gitlab-ci.yml}) versionné dans le dépôt.

    \item[Healthcheck (\texttt{/health})] Endpoint exposant l'état de santé de l'API (accès à la base, mémoire), implémenté avec @nestjs/terminus et interrogé par la supervision.

    \item[MCO] Maintien en Condition Opérationnelle~: ensemble des activités assurant qu'un logiciel en production reste disponible, sûr et à jour.

    \item[Merge Request (MR)] Demande de fusion d'une branche vers une autre sur GitLab, soumise à la validation du pipeline CI avant intégration (équivalent GitLab de la pull request).

    \item[Migration] Script versionné décrivant une évolution de la structure de la base de données, appliqué via Prisma.

    \item[NestJS] Framework Node.js pour construire des applications backend modulaires et évolutives. Utilisé pour l'API de BrackX.

    \item[Node.js] Environnement d'exécution JavaScript côté serveur.

    \item[npm audit] Commande signalant les vulnérabilités connues dans les dépendances d'un projet Node.js.

    \item[ORM] Object-Relational Mapping~: technique faisant correspondre les tables d'une base relationnelle à des objets typés du code.

    \item[pino] Bibliothèque de journalisation pour Node.js produisant des journaux structurés (JSON) exploitables pour le diagnostic.

    \item[Pipeline] Ensemble d'étapes automatisées (lint, build, tests) exécutées à chaque modification du code.

    \item[Poules] Format de tournoi où les participants d'un groupe s'affrontent, un classement déterminant les qualifiés.

    \item[PostgreSQL] Système de gestion de base de données relationnelle utilisé par BrackX.

    \item[Préproduction] Environnement reproduisant la production, utilisé pour valider un correctif ou une évolution avant sa mise en service.

    \item[Prisma] ORM moderne pour Node.js et TypeScript, suivant une approche schéma-first avec migrations versionnées et client typé.

    \item[Prometheus / Grafana] Couple d'outils de collecte et de visualisation de métriques, cité comme dispositif de supervision plus lourd, surdimensionné pour un déploiement mono-serveur.

    \item[Qualification inter-phases] Règle définissant combien de participants passent d'une phase à la suivante et selon quel parcours.

    \item[Recette] Phase de tests fonctionnels validant l'application au regard des résultats attendus avant livraison.

    \item[Renovate] Outil de veille et de mise à jour automatisée des dépendances, intégré à GitLab, qui ouvre des merge requests de montée de version.

    \item[RGPD] Règlement Général sur la Protection des Données~: cadre légal européen encadrant le traitement des données personnelles.

    \item[Ronde suisse] Format de tournoi où, à chaque ronde, les participants de score voisin sont appariés sans jamais se réaffronter. Le classement s'établit aux points, sans élimination directe.

    \item[Rollback] Retour à une version précédente de l'application en cas de problème après déploiement.

    \item[Rybbit] Solution open-source auto-hébergée réunissant supervision d'uptime, mesure de performance (Core Web Vitals) et analyse d'audience. Outil de supervision de BrackX.

    \item[SAST] Static Application Security Testing~: analyse statique du code source à la recherche de vulnérabilités de sécurité (ici Semgrep).

    \item[SCA] Software Composition Analysis~: analyse des dépendances tierces à la recherche de vulnérabilités connues (ici Trivy et \texttt{npm audit}).

    \item[Semgrep] Outil open-source d'analyse statique de sécurité (SAST), équivalent de la brique SAST de Checkmarx.

    \item[SonarQube] Plateforme d'analyse de qualité du code (bogues, duplication, complexité, couverture, points de sécurité), utilisée en amont pour détecter la dette technique.

    \item[Sonde] Mécanisme de mesure d'un aspect du système (disponibilité, santé, performance) alimentant la supervision.

    \item[Supervision] Surveillance continue d'une application en production afin de détecter au plus tôt toute indisponibilité ou dégradation.

    \item[Tiebreak (départage)] Cascade de critères appliquée pour départager des participants à égalité (confrontation directe, différence de scores, barrage).

    \item[TMA] Tierce Maintenance Applicative~: maintenance et évolution de l'application après livraison.

    \item[Trivy] Outil open-source d'analyse de composition logicielle et d'images (SCA), équivalent de la brique SCA de Checkmarx.

    \item[TypeScript] Extension typée de JavaScript apportant robustesse et maintenabilité au code.

    \item[Uptime (disponibilité)] Part du temps durant laquelle l'application répond correctement~; indicateur central de la supervision.

    \item[Versionnement sémantique] Convention de numérotation des versions \texttt{major.minor.patch} (par ex. \texttt{v0.6.1}).

    \item[WebSocket] Protocole de communication bidirectionnelle temps réel, envisagé via les gateways NestJS pour les futures notifications de résultats.
\end{description}
